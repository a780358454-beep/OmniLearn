# خطة المشروع v3.3 — CodeSphere (Harmash Style + Open Access)

> هذا الملف هو مصدر الحقيقة الوحيد والمعتمد لمعمارية المشروع.
> آخر تحديث: 2026-10-30 (الإصدار v3.3)

## 1. الهوية والهدف العام
**CodeSphere:** منصة ومحرك تعليم برمجة وعلوم حاسوب حصري وعام (Android & Web-ready).
- **التخصص الحصري:** برمجة، هندسة برمجيات، تطوير ويب وموبايل، خوارزميات وهياكل بيانات فقط 100%. يُمنع نهائياً أي محتوى طبي أو خارج علوم الحاسوب.
- **التعلم المفتوح (Open-Access على نمط هرمش Harmash):** إلغاء القفل الإجباري للدروس؛ يحق لأي طالب تصفح وقراءة ودراسة أي درس في أي مادة بحرية تامة دون إجباره على إنهاء الدروس السابقة، مع الإبقاء على شجرة المهارات التفاعلية بنقاط الـ XP والمستويات، وقصر القفل التقييمي فقط على "اختبار الشهادة النهائي للمقرر".
- **النمط المزدوج للمحتوى (Harmash Reference Articles + Interactive Cards):** دعم نمط المقال المرجعي الشامل الطويل المماثل لموقع "هرمش" (شروحات نظرية عميقة، جداول، وأمثلة كود برمجية احترافية مع زر نسخ فوري) إلى جانب نمط البطاقات التفاعلية السريعة والاختبارات التفاعلية السبعة.

## 2. القرارات المعمارية المقفلة v3.3 (Locked Decisions)
| # | القرار المعماري | الوصف والتنفيذ |
|---|---|---|
| 1 | **الحسابات والأدوار** | مدير النظام المبدئي: `abodi` (مُجزأة بـ SHA-256 + Salt). تسجيل ذاتي للطلاب. فتح المساهمة لجميع المستخدمين بنظام اعتماد إداري. |
| 2 | **التعلم المفتوح (Open-Access)** | كافة الدروس المعتمدة مفتوحة للقراءة دون قفل تسلسلي إجباري. القفل محصور فقط في الاختبار النهائي المانح للشهادة (≥ 80%). كما يحق للطالب التبديل الحر بين كافة المسارات والمناهج المعتمدة دون اشتراط صلاحيات إدارية. |
| 3 | **النمط الثلاثي للدروس (Triple-Mode: Harmash + Sololearn + Duolingo)** | التبديل الفوري السلس بين ثلاثة أنماط تعليمية متكاملة: عارض المقال المرجعي الشامل (Harmash)، عارض البطاقات التفاعلية (Sololearn)، وتحديات الخطوات الخاطفة السريعة بنظام القلوب والسلسلة (Duolingo). |
| 4 | **الأمان والتطهير (`ContentSanitizer`)** | تطهير إلزامي لكافة مدخلات المقالات والأسئلة لمنع حقن السكربتات (XSS/Script Injection) مع عرض الأكواد كـ Read-Only Monospace. |
| 5 | **حماية الملكية والنسخ الظلية للتعديل (`Shadow Versioning & Author Guard`)** | التحقق الصارم من ملكية المؤلف؛ يُمنع أي مستخدم عادي من تعديل دروس النظام أو دروس غيره. وفي حال تعديل درسه المعتمد، لا تمس النسخة المنشورة للطلاب، بل تُخزَّن كمسودة ظل معلقة (`pendingUpdatePayload`) لمراجعة الإدارة. |
| 6 | **سلسلة المراجعة التفاعلية (`Review Thread`)** | تحويل الملاحظات الفردية إلى سلسلة تراسل وملاحظات ثنائية بين المساهم والمدير. |
| 7 | **إلغاء رفع الكورسات الكاملة من المستخدمين** | حصر مساهمة الطلاب والمشرفين في إضافة "الدروس والاختبارات الفردية" فقط لمنع تشتت هيكل المناهج المعتمدة من الإدارة. |
| 8 | **عزل التخزين وثبات المعرفات** | مفاتيح التقدم (`omni_progress_v2_$userId`) مفصولة تماماً عن المناهج (`omni_curricula_v2`)، وثبات معرّفات الدروس (`Immutable Lesson IDs`). |
| 9 | **المزامنة السحابية الذكية (Cloud Sync & Offline Queue)** | حفظ المسودات محلياً بدون إنترنت، ورفعها بضغطة واحدة فور توفر الاتصال عبر `CloudSyncService`. |
| 10 | **الإعلانات الاختيارية المكافئة** | إعلانات مكافئة اختيارية فقط (Reward Ads) يتحكم المدير بتفعيلها أو إيقافها، ولا تفرض قسراً على الطلاب. |

## 3. المعمارية الهيكلية للمشروع
```
lib/
  core/
    design/         ← الرموز التصميمية والألوان والأحجام
    i18n/           ← الترجمة الفورية ثنائية اللغة (Arabic RTL / English LTR)
    models/         ← نماذج التعلم والمستخدمين وهرمش والنسخ الظلية
    repositories/   ← طبقة التخزين المحلي المعزول (SharedPreferences)
    security/       ← تجزئة كلمات السر وتطهير المحتوى (ContentSanitizer)
    services/       ← إدارة الحالة الشاملة (AppStateService) والربط السحابي (CloudSyncService)
    widgets/        ← المكونات المشتركة
  features/
    admin/          ← بوابة المدير (الاعتماد، الحسابات، السحابة، الهوية)
    auth/           ← الدخول، التسجيل، وتغيير كلمة السر
    creator/        ← استوديو التأليف، عزل اللغات، والمساهمات
    learner/        ← الشاشة الرئيسية، المقالات المرجعية، البطاقات، وحلبة الاختبارات
    shared/         ← الحارس الأمني (RoleGuard)، والشريط العلوي (TopNavbar)
```

## 4. خطة مراحل التنفيذ v3.3
1. **المرحلة 1 (Phase 1):** ترقية نماذج البيانات والمقالات المرجعية على نمط هرمش (`HarmashArticle Mode`) وتفعيل التعلم الحر المفتوح.
2. **المرحلة 2 (Phase 2):** بناء فلتر الأمان وتطهير المدخلات (`ContentSanitizer`) وتطبيق النسخ الظلية للتعديلات (`Shadow Versioning`).
3. **المرحلة 3 (Phase 3):** تفعيل سلسلة محادثات المراجعة التفاعلية (`Review Thread`) بين الإدارة والمستخدم والإشعارات الموجهة.
4. **المرحلة 4 (Phase 4):** اختبارات الوحدة الشاملة وتأكيد خلو النظام من أي أخطاء أو تعارضات.
